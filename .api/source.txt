package source // import "github.com/withObsrvr/nebu/pkg/source"

Package source provides abstractions for streaming Stellar ledger data.

FUNCTIONS

func ResolveLast(w LedgerWindow, n uint32) (start, end uint32, err error)
    ResolveLast returns the bounded range covering the last n ledgers of w.

    It counts back from Latest and does not consult Oldest, because Oldest
    is not a reliable floor (see LedgerWindow.Covers). Serviceability is the
    stream's to prove: the resolved range is always the full n ledgers that
    were asked for, so a source that cannot serve it fails the run rather than
    quietly returning a shorter dataset that looks complete.


TYPES

type LedgerSource interface {
	// Stream sends ledgers in the range [start, end] (inclusive) to the out channel.
	// The implementation must close the out channel when done or on error.
	//
	// Stream respects context cancellation and will stop streaming if ctx is cancelled.
	// Returns an error if the range cannot be prepared or if ledger retrieval fails.
	Stream(ctx context.Context, start, end uint32, out chan<- xdr.LedgerCloseMeta) error

	// Close releases any resources held by the source.
	Close() error
}
    LedgerSource streams LedgerCloseMeta objects from a Stellar data source.
    Implementations must be safe for concurrent use.

type LedgerWindow struct {
	// Oldest is the lowest ledger the source still holds.
	Oldest uint32
	// Latest is the highest ledger the source holds.
	Latest uint32
}
    LedgerWindow is the range of ledgers a source can currently serve.

    Both bounds matter. Latest is what "the last N ledgers" counts back from;
    Oldest is what makes the difference between refusing a range the source
    cannot serve and discovering that fact part-way through a backfill.

func (w LedgerWindow) Covers(start uint32) bool
    Covers reports whether start is at or above the oldest ledger the source
    said it holds.

    Advisory only. An archive-backed RPC endpoint reports a retention window
    covering its last few dozen ledgers and then serves history millions of
    ledgers deeper — archive-rpc.lightsail.network reports a 64-ledger window
    and returns ledger 60200000 without complaint. So a false here means "the
    source did not claim to have this", not "the source cannot serve it",
    and it is worth a warning rather than a refusal.

func (w LedgerWindow) String() string
    String renders the window for a diagnostic line.

type RawLedgerFunc func(sequence uint32, raw []byte) error
    RawLedgerFunc receives one ledger's undecoded XDR, in sequence order.

    raw is only valid until the function returns. The underlying stream reuses
    the slice on its next step, so anything kept beyond the call must be copied.
    Returning an error stops the stream and that error reaches the caller of
    RawLedgerSource.StreamRaw unwrapped.

type RawLedgerSource interface {
	// StreamRaw streams ledgers [start, end] to fn and reports how many it
	// delivered. end == 0 means unbounded.
	//
	// The count is part of the contract: a bounded range that returns fewer
	// ledgers than it asked for has not failed in any way the error can show,
	// so the caller is the only thing that can notice.
	StreamRaw(ctx context.Context, start, end uint32, fn RawLedgerFunc) (uint32, error)
}
    RawLedgerSource is implemented by a LedgerSource that can hand out each
    ledger's bytes without decoding them.

    It is a separate interface rather than a method on LedgerSource, for the
    same reason as WindowedSource: LedgerSource is part of the stable surface
    and adding a method there would break every external implementation.
    Callers type-assert for this one, so a source that cannot answer simply does
    not implement it.

    It exists because decoding is wasted work for a consumer that only wants
    to store or forward the bytes. `nebu fetch` writes raw ledger XDR, and
    going through LedgerSource.Stream would decode every ledger and re-encode
    it — paying for the round trip on nebu's bulk-transfer path, and making the
    output depend on the encoder rather than on what the source served.

    The callback is deliberate. A channel of []byte would hand the receiver
    memory that the stream overwrites on its next step, and nothing about the
    resulting corruption would be loud.

type WindowedSource interface {
	LedgerWindow(ctx context.Context) (LedgerWindow, error)
}
    WindowedSource is implemented by a LedgerSource that can report which
    ledgers it currently holds.

    It is a separate interface rather than a method on LedgerSource because
    LedgerSource is part of the stable surface: adding a method there would
    break every external implementation. Callers type-assert for this one,
    so a source that cannot answer simply does not implement it.

    Note that the answer is source-relative and the two sources disagree by
    design. An RPC endpoint reports the network tip and its own retention floor;
    an archive reports the newest and oldest ledgers that have been *exported*,
    which lags the network. "The last 100 ledgers" is therefore a different
    hundred depending on where it is asked, which is why callers are expected to
    report the range they resolved.
