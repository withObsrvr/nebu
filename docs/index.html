Quickstart

  1. 1.Install the CLI

    go install github.com/withObsrvr/nebu/cmd/nebu@latest
export PATH="$HOME/go/bin:$PATH"

  2. 2.Discover and install a processor

    nebu list
nebu install token-transfer

  3. 3.Stream events

    token-transfer --start-ledger 60200000 --end-ledger 60200001 | jq

  4. 4.Compose a pipeline

    token-transfer --start-ledger 60200000 \
  | jq -c 'select(.transfer.assetCode == "USDC")' \
  | dedup --key meta.txHash \
  | json-file-sink --out usdc.jsonl

How it works

nebu (pronounced "neh-boo") is built on the supported building blocks Stellar provides for modern indexing — RPC-backed ledger access, the ingest SDK, XDR-native extraction — and packages them into a stable Go contract, standalone processor binaries, and Unix-composable pipelines.

Stellar RPC --mode rpc (default) Recent ledgers, live tail
GCS / S3 archive --mode archive Full history, bulk backfill
LedgerCloseMeta (XDR)
Origin token-transfer · contract-events · contract-invocation
typed events (JSON, _schema=nebu.*.v1)
Transform usdc-filter · amount-filter · dedup · time-window
filtered events (meta preserved)
Sink json-file-sink · nats-sink · postgres-sink · duckdb · jq

Two ledger sources, one contract. Use --mode rpc for live tailing and recent-range backfills. Use --mode archive against a GCS or S3 ledger archive to read deep history without RPC rate limits — the same XDR, the same processors, the same JSON on the way out.

Everything downstream of the origin communicates via Unix pipes (stdin/stdout, newline-delimited JSON) — trivial to compose with jq, duckdb, or anything that reads a stream.

Named after the Nebuchadnezzar from The Matrix. nebu is the vessel that carries data from the on-chain truth to your applications.

Features

Stable contract

pkg/processor and pkg/source are committed-stable, enforced by CI against API snapshots in .api/. Build your own processor, ship it as its own binary.

Unix pipes

No daemon. No orchestrator. Origin | Transform | Sink, composed with the same pipe you've used since 1973. Pipe to jq, to duckdb, to tee.

Archive mode

Fetch raw XDR directly from GCS or S3 at 100–500 ledgers/sec — bypassing RPC rate limits entirely. Backfill Stellar's full history into a data lakehouse without a single custom worker.

Self-describing processors

Every processor emits a JSON-schema-valid --describe-json manifest. Agents and tools can discover flags, inputs, outputs, and schema IDs without reading source.

Schema versioning

Every event carries _schema and _nebu_version. Field rename? Bump the version. Your downstream queries never break silently.

Community registry

Register any Git repo as a processor source via description.yml. nebu install your-processor just works.

Resumable fetch

Opt-in checkpoints resume bounded file backfills from the last durable ledger. Output is synchronized before checkpoint advancement, with range and path-alias validation built in.

Explicit status

OSC 7501 reports interactive state to terminals. Automation consumes the separate, stable nebu.status.v1 NDJSON lifecycle and progress stream.

Event format

Processors write newline-delimited JSON to stdout. Every event carries the nebu envelope alongside its payload data.

Cookbook

Historical archives

Read deep history from the public aws-public-blockchain S3 archive — no AWS account, no RPC rate limits.

nebu fetch --mode archive \
  --datastore-type S3 \
  --bucket-path "aws-public-blockchain/v1.1/stellar/ledgers/pubnet" \
  --region us-east-2 \
  62080000 62080100 | gzip > historical.xdr.gz

Premium RPC

Use authenticated RPC endpoints via NEBU_RPC_AUTH for higher throughput and private lanes.

export NEBU_RPC_AUTH="Api-Key YOUR_KEY"
token-transfer \
  --rpc-url https://rpc-pubnet.nodeswithobsrvr.co \
  --start-ledger 60200000 --end-ledger 60200100

Complete pipeline

Extract → filter → dedupe → store, composed with only the shell's pipe.

token-transfer --start-ledger 60200000 \
  | jq -c 'select(.transfer.assetCode == "USDC")' \
  | dedup --key meta.txHash \
  | json-file-sink --out usdc.jsonl

Fan out with tee

One stream, many sinks. Live NATS for consumers, a JSONL archive on disk, a human-readable tail in the terminal.

token-transfer --start-ledger 60200000 \
  | tee >(nats-sink --subject "stellar.live" --jetstream) \
  | tee >(json-file-sink --out archive.jsonl) \
  | jq -r '"L\(.meta.ledgerSequence): \(.transfer.amount)"'

DuckDB analytics

SQL aggregations directly over the stream. No database setup, no schema, no ETL job.

token-transfer --start-ledger 60200000 --end-ledger 60200100 \
  | duckdb -c "
    SELECT json_extract_string(transfer,'\$.assetCode') AS asset,
           COUNT(*) AS n
    FROM read_json('/dev/stdin')
    WHERE transfer IS NOT NULL
    GROUP BY asset ORDER BY n DESC"

Fetch once, process many

Capture raw XDR once, replay through any number of processors. Great for backfills and schema diffs.

nebu fetch 60200000 60200100 > ledgers.xdr
cat ledgers.xdr | token-transfer | jq 'select(.transfer)'
cat ledgers.xdr | contract-events | grep -i swap
Separate fetch from process nebu fetch passes raw LedgerCloseMeta XDR directly from RPC or archive storage to stdout, without a decode/re-encode cycle — capture a ledger range once and replay it through any number of processors. Great for backfills, regression tests, and comparing two schema versions over the same ledgers.

See also nebu(1) › Examples for the exhaustive reference, and docs/DUCKDB_COOKBOOK.md for deeper SQL recipes.
