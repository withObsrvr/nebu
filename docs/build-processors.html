Processor author path

Build custom processors against
the stable nebu contract.

nebu is intentionally two things: a user-facing CLI and a minimal, stable contract for authors. If you're building your own processor, focus on pkg/processor, pkg/source, and the --describe-json protocol.

Origin

Read ledgers from a source and emit events. Use this when you are extracting new domain objects from Stellar data.

Transform

Read JSON events from stdin, filter or enrich them, and emit new JSON events to stdout.

Sink

Read JSON events from stdin and produce side effects such as writing files or publishing to external systems.

Stable surfaces

  • pkg/processor — Processor, Origin, Transform, Sink, Emitter, Reporter, and describe-protocol types
  • pkg/source — the LedgerSource contract
  • --describe-json — machine-readable introspection for tools and registries
  • registry.yaml and description.yml — stable discovery formats

Recommended workflow

  1. Depend only on the stable packages.
  2. Implement the processor type you need.
  3. Expose --describe-json.
  4. Ship your binary as its own Go module.
  5. Register it in an external registry repo.
