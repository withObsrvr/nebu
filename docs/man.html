nebu(1)

nebu — composable processors for Stellar ledger data. Origin, transform, and sink programs connected with Unix pipes.

General Commands Manual · rev 2026-08-03
On this pageSynopsisDescriptionCommandsOptionsEnvironmentFilesExit statusExamplesSchemaSee also

Synopsis

nebu [OPTIONS] COMMAND [ARGS]...
nebu list
nebu install <processor>
nebu fetch [--mode rpc|archive] <start> <end>
<processor> --start-ledger N [--end-ledger N]

Description

nebu packages Stellar's modern indexing primitives — RPC-backed ledger access, the ingest SDK, XDR-native extraction — into a stable Go contract, standalone processor binaries, and Unix-composable pipelines.

The nebu binary is intentionally minimal. It discovers processors via a registry.yaml, installs them with go install, and can fetch raw ledger XDR. Actual event extraction happens in standalone processor binaries that speak newline-delimited JSON over stdout.

Pipelines are composed with the shell's own pipe. There is no daemon, no orchestrator, no YAML pipeline file.

Commands

nebu list

Show all processors known to the embedded registry and the external processor registry. Lists name, type, location, and description.

$ nebu list

nebu install <processor>

Resolve the processor in the registry and install its binary to $GOPATH/bin via go install. Works for in-repo educational examples and external processors whose Go module or prebuilt release installs cleanly.

$ nebu install token-transfer

nebu fetch <start> <end>

Fetch raw LedgerCloseMeta XDR for a ledger range and write it to stdout. RPC and archive modes pass the backend's XDR bytes directly through without decoding and re-encoding each ledger. The output remains compatible with existing processors and saved .xdr files.

  • --mode rpc — (default) stream from a Stellar RPC endpoint
  • --mode archive — read from a GCS/S3 ledger archive (e.g. the public aws-public-blockchain bucket)
$ nebu fetch 60200000 60200100 > ledgers.xdr
$ cat ledgers.xdr | token-transfer | jq

<processor> --start-ledger N [--end-ledger N]

Run an installed processor. Origins read ledgers (from RPC or stdin) and emit typed events as NDJSON on stdout. Transforms and sinks read NDJSON from stdin.

$ token-transfer --start-ledger 60200000 --end-ledger 60200001
$ token-transfer --start-ledger 60200000

<processor> --describe-json

Emit a JSON-schema-valid manifest of the processor's flags, inputs, outputs, and schema IDs. The agent-legible contract — tooling and LLMs can discover capabilities without reading source.

$ token-transfer --describe-json | jq .outputs

Options

OptionDescription
--rpc-url <url>Stellar RPC endpoint. Overrides NEBU_RPC_URL.
--network <id>Network: mainnet, testnet, or a full passphrase.
--start-ledger NStarting ledger sequence (inclusive).
--end-ledger NEnding ledger sequence (inclusive). Omit it for unbounded streaming.
--last NUse the most recent N ledgers the source holds instead of an explicit range, so you do not have to look a sequence number up first. Mutually exclusive with explicit ledgers, with --start-ledger, and with --checkpoint — a checkpoint resumes a fixed range and --last resolves a new one as the chain advances. The resolved range is reported on stderr. Accepted by every origin processor; overrides NEBU_LAST.
-f, --followStream ledgers continuously from --start-ledger, equivalent to an end ledger of 0.
--output <path>Write raw XDR to a file instead of stdout. An output destination, not a format.
--rpc-header <h>Extra HTTP header for RPC, as 'Key: Value'. Repeatable.
--on-ledger-error <m>What a ledger that cannot be processed completely means for the run: best-effort continues and reports coverage, strict stops and exits 8. Default: best-effort. Accepted by every origin processor; overrides NEBU_ON_LEDGER_ERROR.
--buffer-size NLedgers buffered in archive mode. 0, the default, tunes it from the datastore layout.
--num-workers NParallel archive fetch workers. 0, the default, tunes it from the datastore layout.
--ledgers-per-file NOverride the archive's ledgers-per-file layout. 0, the default, reads it from the datastore manifest; set it for a bucket with no manifest, or to have your value checked against one.
--files-per-partition NOverride the archive's files-per-partition layout, on the same terms as --ledgers-per-file.
--quietSuppress informational output. Only NDJSON events on stdout.
--program-status <mode>OSC 7501 terminal status: auto, always, or never. Default: auto.
--status-file <path>Write stable nebu.status.v1 NDJSON lifecycle and progress records to a dedicated file.
--checkpoint <path>Persist resumable state for a bounded fetch. Use with file output and keep the two paths distinct.
--checkpoint-interval NLedgers between durable checkpoint writes. Default: 1.
-v, --versionPrint version information and exit.
-h, --helpShow help message and exit.

Exit status

CodeMeaning
0Success.
1General error (see stderr).
2Invalid usage or configuration.
3Requested processor or ledger range was not found or is ambiguous.
4RPC or archive source is unavailable.
8Ran, but the output is incomplete: a ledger could not be processed completely and --on-ledger-error strict is in effect. Distinct from 4 on purpose — 4 is worth retrying, 8 will fail the same way.
130Interrupted by SIGINT / Ctrl+C.

Examples

Extract token transfers

$ token-transfer --start-ledger 60200000 --end-ledger 60200100

USDC transfers to a file

$ token-transfer --start-ledger 60200000 --end-ledger 60200100 \
  | usdc-filter \
  | json-file-sink --out usdc.jsonl

SQL analytics with DuckDB, no database

$ token-transfer --start-ledger 60200000 --end-ledger 60200100 \
  | duckdb -c "
    SELECT json_extract_string(transfer, '\$.assetCode') AS asset,
           COUNT(*) AS transfers,
           SUM(CAST(json_extract_string(transfer, '\$.amount') AS DOUBLE)) AS volume
    FROM read_json('/dev/stdin')
    WHERE transfer IS NOT NULL
    GROUP BY asset ORDER BY volume DESC"

Fan-out: NATS + file + terminal

$ token-transfer --start-ledger 60200000 \
  | tee >(nats-sink --subject "stellar.live" --jetstream) \
  | tee >(json-file-sink --out archive.jsonl) \
  | jq -r '"Ledger \(.meta.ledgerSequence): \(.transfer.amount)"'

Archive-mode backfill from the AWS public bucket

No AWS credentials required — the SDK falls back to anonymous access. Pubnet only; testnet uses a different (non-Galexie) layout in this bucket.

$ nebu fetch --mode archive \
  --datastore-type S3 \
  --bucket-path "aws-public-blockchain/v1.1/stellar/ledgers/pubnet" \
  --region us-east-2 \
  62080000 62081000 \
  | gzip > historical.xdr.gz

Schema

Every event carries two self-describing fields:

FieldMeaning
_schemaSchema identifier (e.g. nebu.token_transfer.v1).
_nebu_versionnebu version that produced the event.

Breaking changes bump the schema version. Non-breaking additions (new fields, new event types) do not. Filter by _schema in your downstream queries to stay compatible across rolls.
